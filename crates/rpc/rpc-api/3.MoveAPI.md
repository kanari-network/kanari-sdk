# Kanari Move VM API Guide

This guide explains how to use the API for Move Virtual Machine on Kanari Blockchain.

## 1. Execute VM Function
Call a function in a Move Module:

```bash
curl -X POST -H "Content-Type: application/json" -d '{
  "jsonrpc": "2.0",
  "method": "vm_execute",
  "params": {
    "module_id": "0x1234::counter",
    "function": "increment",
    "args": [123],
    "gas_budget": 10000
  },
  "id": 1
}' http://your.node.address:30030
```

## 2. Get Module Information
View information about a deployed module:

```bash
curl -X POST -H "Content-Type: application/json" -d '{
  "jsonrpc": "2.0",
  "method": "vm_get_module",
  "params": {
    "module_id": "0x1234::counter"
  },
  "id": 1
}' http://your.node.address:30030
```

## 3. List All Modules
List all modules:

```bash
curl -X POST -H "Content-Type: application/json" -d '{
  "jsonrpc": "2.0",
  "method": "vm_list_modules",
  "params": [],
  "id": 1
}' http://your.node.address:30030
```

## Module Structure
The Move VM module on Kanari has the following structure:
- `module_id`: Module identifier in the format "0x{address}::{name}"
- `name`: Module name
- `address`: Blockchain address where the module is deployed
- `public_functions`: List of public functions that can be called
- `deploy_block_height`: Block height at which the module was deployed

## Gas System
Function execution on the VM uses gas calculated from:
- Computational complexity
- Amount of data written to storage
- Network congestion conditions

You can specify a `gas_budget` to limit the maximum cost for function calls

## Best Practices
1. Verify function names and parameter types carefully
2. Use appropriate gas budgets to avoid transaction failures
3. Check results and handle any errors that occur

## Limitations
1. Modules must be deployed to the blockchain before functions can be called
2. Only public functions can be called
3. Transactions will fail if gas exceeds the specified budget
