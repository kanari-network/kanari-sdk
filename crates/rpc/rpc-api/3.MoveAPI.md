# Kanari Move VM API Guide

## Introduction

The Kanari Move VM API provides a set of JSON-RPC endpoints for interacting with Move modules deployed on the Kanari blockchain. This API allows developers to list available modules, get specific module details, execute module functions, and view transaction history.

## API Endpoints

### List Modules

Lists all deployed Move modules with pagination support.

**Method:** `list_modules`

**Parameters:**
- `limit` (optional): Maximum number of modules to return (default: 10, max: 100)
- `offset` (optional): Number of modules to skip (for pagination)

**Example Request:**
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "list_modules",
  "params": {
    "limit": 5,
    "offset": 0
  }
}
```

**Example Response:**
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "modules": [
      {
        "module_id": "0x1::coin",
        "address": "0x1",
        "name": "coin",
        "bytecode_size": 4280,
        "deploy_tx_id": "tx_0123456789abcdef",
        "deploy_block_height": 1024,
        "deploy_time": 1635739200,
        "public_functions": ["mint", "burn", "transfer"]
      },
      {
        "module_id": "0x2::token",
        "address": "0x2",
        "name": "token",
        "bytecode_size": 2844,
        "deploy_tx_id": "tx_abcdef0123456789",
        "deploy_block_height": 1025,

        "public_functions": ["create", "mint", "transfer"]
      }
    ],
    "total": 2,
    "limit": 5,
    "offset": 0
  }
}
```

### Get Module

Returns detailed information about a specific module.

**Method:** `get_module`

**Parameters:**
- `module_id` (required): The ID of the module in the format `<address>::<name>`

**Example Request:**
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "get_module",
  "params": {
    "module_id": "0x1::coin"
  }
}
```

**Example Response:**
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "module_id": "0x1::coin",
    "address": "0x1",
    "name": "coin",
    "bytecode_size": 4280,
    "deploy_tx_id": "tx_0123456789abcdef",
    "deploy_block_height": 1024,
    "deploy_time": 1635739200,
    "abi": {
      "structs": [
        {
          "name": "Coin",
          "fields": [
            {"name": "value", "type": "u64"}
          ]
        }
      ],
      "public_functions": [
        {
          "name": "mint",
          "params": ["&signer", "u64"],
          "return_type": "Coin"

        {
          "name": "burn",

          "return_type": "u64"
        },
        {
          "name": "transfer",
          "params": ["&signer", "address", "Coin"],
          "return_type": []

  }
}
```

### Execute Function

Executes a function in a deployed module.

**Method:** `execute_function`

**Parameters:**
- `module_id` (required): The ID of the module in the format `<address>::<name>`
- `function` (required): The name of the function to execute
- `args` (optional): Array of arguments to pass to the function
- `sender` (optional): The address that will execute the function (default: "0x1")
- `gas_budget` (optional): Maximum gas to use for the transaction (default: 1,000,000)

**Example Request:**
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "execute_function",
  "params": {
    "module_id": "0x1::coin",
    "function": "mint",
    "args": [
      {"address": "0x2a2a2a2a2a2a2a2a"},
      {"u64": 100}
    ],
    "sender": "0x2a2a2a2a2a2a2a2a",
    "gas_budget": 1000000
  }
}
```

**Example Response:**
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "status": "success",
    "tx_id": "vm_tx_0123456789abcdef",
    "module": "0x1::coin",
    "function": "mint",
    "gas_used": 1000,
    "gas_display": "0.000001 KARI",
    "execution_time_ms": 15,
    "block_height": 1024,
    "timestamp": 1635739200,
    "return_value": {
      "type": "Coin",
      "value": 100
    }
  }
}
```

## Error Handling

The API follows the JSON-RPC 2.0 specification for error responses. Common error codes include:

- `-32000`: Internal error (server-side error)
- `-32001`: Invalid parameters (client-side error)
- `-32004`: Resource not found
- `-32005`: Execution error (function call failed)

**Example Error Response:**
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32004,
    "message": "Module not found: 0x1::unknown_module"
  }
}
```

## API Conventions

### Module ID Format

A module ID consists of an address and a module name in the format: `<address>::<module_name>`. For example:
- `0x1::coin`
- `0x3a3a3a3a::token`

### Address Format

Addresses should be specified as hexadecimal strings, preferably with the `0x` prefix. For example:
- `0x1`
- `0x3a3a3a3a3a3a3a3a`

### Argument Types

When executing functions, arguments should be provided in their appropriate format:

- **Address**: Hexadecimal string, e.g., `"0x1"`
- **Integer**: Numeric value, e.g., `100` for u64
- **Boolean**: Boolean value, `true` or `false`
- **String**: String value, e.g., `"hello world"`

## Move Module Development

For information on how to create and deploy Move modules, please refer to the Kanari Move Module Development Guide or use the CLI commands:

```bash
# Create a new module
kari move new my_module

# Build the module
kari move build

# Deploy to the blockchain
kari move publish

# Call a function in a deployed module
kari move call --module-id 0x123::my_module --function my_function --args type:value
```

## API Rate Limits

To ensure network stability, the following rate limits apply:
- List/Get operations: 100 requests per minute
- Execute operations: 10 requests per minute per address

## Security Best Practices

1. Always specify a reasonable gas budget for function execution
2. Use a dedicated address for important operations
3. Verify module source code before interacting with it
4. Test functions in a development environment before production use
